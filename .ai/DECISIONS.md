# Decisions

- **D1 Monorepo**: pnpm workspaces; packages export TS source (Next transpiles; worker bundled with esbuild/tsx). Rationale: one type system, no publish step.
- **D2 Stack**: Next 16.3 + React 19.3, Tailwind 4.3, Drizzle 0.45 + postgres-js, pg-boss 12 (Postgres-backed durable queue — no Redis), Better Auth 1.7, Zod 4, Vitest, Playwright 1.63. TypeScript pinned to 5.9.3 (TS 7 native port breaks typescript-eslint; ESLint pinned 9.39 because eslint-config-next breaks on 10).
- **D3 Auth topology**: auth API lives on the app (APP_URL/api/auth). Marketing site validates the same session cookie server-side (shared secret + DB) → no auth-state flash. Production uses `AUTH_COOKIE_DOMAIN=gigpilot.ai` for cross-subdomain cookies; locally both apps share the Tailscale host (cookies ignore ports). Cookie prefix `gigpilot`.
- **D4 Tenancy**: every sign-up gets its own workspace (tenant); demo workspaces are seeded with history and fed by the mock source through the real pipeline. SIGNUP_MODE=invite available for public deployment.
- **D5 Economics**: deterministic calculator; LLMs only estimate quantities. Price catalog in `packages/economics/src/catalog.ts` with verification date. Fixed budget price = range midpoint; hourly = clamped rate × estimated hours; unknown → incomplete.
- **D6 Spend safety**: `PAID_PROVIDER_DAILY_BUDGET_USD=0` and tenant `dailyPaidSpendLimitUsd=0` by default → paid providers never called; mock/test mode used. GX is local (cost $0) and used for cheap tasks.
- **D7 AgentOS**: no runtime supervision API exists in AgentOS today (control center is read-only dashboard; supervisor has no job registry). GigPilot runs its own durable orchestrator and exposes a pull-only token-protected supervision API; an `AgentOSAdapter` boundary allows push later. Project registration descriptor prepared in `ops/agentos/` but NOT registered (registration would trigger Hermes Kanban work on this repo).
- **D8 Marketplaces**: Upwork = user-directed search only, no background polling, 24h cache TTL, manual submission. Freelancer = API search + bid after explicit owner approval. Contra/Fiverr = paste-in or forwarded email. Public feeds with attribution + min poll intervals.
- **D9 Deployment**: Docker Compose project `gigpilot`, loopback-published ports, and a Caddy `edge` service (host networking, binds only the Tailscale IP, restart-until-bound) for Tailscale exposure. Replaced the initial socat units (2026-09-26) because a TCP proxy cannot supply a trustworthy X-Forwarded-For (security review M2).
- **D12 Two-tier analysis**: instant deterministic triage for every brief (persisted immediately); GX refinement only for pursue candidates on a dedicated single-slot queue, capped per tenant/hour; owner can force deep analysis. gx-code has 1 slot/node (2 total, shared with AgentOS) → GigPilot uses at most 1 (`GX_CODE_MAX_CONCURRENCY`).
- **D13 Estimate accuracy**: `job.estimatedCostUsd` = forecast production spend (fulfilment); contingencies are buffers reflected in the spend limit. The ±20% goal compares actual production spend to that forecast.
- **D14 Least-privilege DB**: runtime role `gigpilot_app` (DML on app tables, owns pgboss schema); owner role `gigpilot` for migrations only.
- **D15 Operator credentials**: server-wide env credentials are available only to operator workspaces (`OPERATOR_EMAILS`); other tenants bring their own keys (GX gateway key shareable, quota-limited). Security review H1.
- **D10 Visual identity**: graphite + international orange ("flight recorder orange"), Schibsted Grotesk / Inter / JetBrains Mono, lines over boxes. See docs/DESIGN.md.
- **D11 GX access**: dedicated LiteLLM virtual key alias `gigpilot` (per-app key convention), containers join external network `gx_gateway` → `http://gx-litellm:4000/v1`. Never gx-max.
- **D16 Operational constants**: engine timing/bounds live in `OPERATIONAL_DEFAULTS` (`packages/config/src/defaults.ts`), never inline: job parallelism 2; initial job spend limit = min(perJobSpendLimitUsd, max(buffered estimate × 2.5, $10)); owner spend-limit ceiling = `PAID_PROVIDER_DAILY_BUDGET_USD` when > 0, else perJobSpendLimitUsd × 10; stuck step = step-execute expiry (30 min) + 15 min grace; delivery: 3 packaging tries per round, ≤ 5 monitor re-queues, stale `preparing` after 15 min; outbox sweeper: idle 5 min, ≤ 5 re-queues then owner alert; awaiting-inputs reminder daily after 24 h; orphan generations after 60 min; spend reservations expire after 120 min; router circuit breaker 3 failures / 60 s cool-down; GX slot wait ≤ `GX_ACQUIRE_TIMEOUT_MS` (120 s). Business limits added to tenant settings: `limits.dailyLocalModelCalls` (150 heavy GX calls/tenant/day) and `limits.maxRefinesPerHour` (6).
- **D17 Reliability semantics**: (a) spend limits are hard — every paid call reserves its expected cost in `spend_reservation` under `pg_advisory_xact_lock('budget:global')` + `('budget:'||tenant)` and settles/releases after; ambiguous submissions and "may still be billed" poll timeouts record a `pending:` paid ledger entry. (b) transitions are claims: `requireChange` + `match {attempts}` so a duplicate or stale attempt can never overwrite newer state (late results are discarded with `step.stale_result`). (c) owner escalations never dead-end: exhausted attempts / repair limit / budget / ambiguous provider outcomes park the step as `blocked` with an owner `blockedReason`; `resumeJob`, `setJobSpendLimit`, `confirmJobInputs` reopen work (new attempt rows; repair grants in `job.extra_repairs`, audited). (d) SIGTERM aborts handlers; an interrupted step returns to `ready` without consuming its attempt (trade-off: a paid creative task interrupted mid-poll is recorded as pending spend and re-submitted on resume — bounded by the reservation). (e) Factory `droid exec` stays `needs_configuration` unless `FACTORY_ALLOW_IN_PROCESS=true` (it would run with the worker's /proc and /run/secrets). (f) live workspaces never ship mock output: QA adds a major `produced_by_mock` finding and Recovery escalates immediately.
